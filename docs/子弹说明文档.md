# Bullet Documentation

**Scene directory**: `res://scenes/bullet/` (PackedScene: root node, art, collision body, `MovementComponent`, etc.)
**Script directory**: `res://scripts/bullet/` (corresponds to the scenes: node structure and exports are handled by the scene, while movement, targeting, and damage are handled by the script)

---

## 1. Script Inheritance

```
Node2D
└── Bullet000Base
    ├── Bullet000NormBase              ← most "standard bullets" start here
    │   ├── BulletLinear000Base        Straight-line
    │   ├── Bullet000ParabolaBase      Parabolic (Bezier)
    │   └── Bullet000TrackBase         Homing (including following the mouse when no target exists)
    └── Bullet016CobCannon (example)   ← special bullet: inherits only the thinnest base class
```

- **`Bullet000Base`**: Body, shadow, `bullet_type`, faction, etc. — the smallest footprint.
- **`Bullet000NormBase`**: hit-detection `Area2D`, impact effects, `speed` / `direction`, `init_bullet`, generic collision handling, and `attack_once`.
- **The three movement base classes**: each calls its own **`$MovementComponent`**'s `physics_process_bullet_move` inside `_physics_process`.
- **Special classes (e.g. Cob Cannon)**: inherit directly from **`Bullet000Base`**, bypassing `NormBase`. These usually have no generic `MovementComponent` either, and instead use their own independent flow (e.g. `init_cannon`, Tween, bomb component).

---

## 2. Initialization (`init_bullet`)

After a standard bullet is fired, it should call **`Bullet000NormBase.init_bullet(dictionary)`**. Common keys are listed in the **`E_InitParasAttr`** enum, for example:

| Key | Meaning |
|----|------|
| `Position` / `Direction` | Starting position and direction |
| `BulletLane` / `IsActivateLane` | Lane, and whether hits are filtered by lane |
| `Enemy` | Optional target for parabolic / homing bullets |
| `EnemyGloPos` | For parabolic bullets: the position used for the landing point if the enemy has already disappeared |

Homing bullets set **`detect_component_global`** inside `init_bullet`. The firing flow must ensure `init_bullet` runs before anything in `_ready` that depends on this global detection reference, to avoid a null reference.

## 3. Movement Components (script path: `scripts/bullet/component/movement/`)

| Script | Role |
|------|------|
| `BulletMovementBase` | On `_ready`, treats `owner` as the bullet's root node (`Bullet000Base`). |
| `BulletMovementLinear` | Advances by `direction * speed` (modifying the root node's local `position`). |
| `BulletMovementParabola` | Bezier-curve landing point; calls `parabola_movement_ready` when the root node's `_ready` runs; can be reset when deflected by an umbrella leaf. |
| `BulletMovementTrack` | `reset_track_movement` switches between homing on an enemy / following the mouse / slowing down with no target; `physics_process_bullet_move` is called every frame by the root node. |

Convention: the **root node** is always responsible for calling the movement component from within `_physics_process`. The movement component itself does **not** independently hook into the global `_physics_process` ordering, which makes it easier to move first and then, e.g., check distance for despawning afterward.

## 4. Special Bullet Example: Cob Cannon

| Item | Details |
|------|------|
| Scene | `bullet_016_cob_cannon.tscn` |
| Script | `scripts/bullet/bullet_016_cob_cannon.gd` → `extends Bullet000Base` |
| Characteristics | Uses **`init_cannon(world_position)`**; the animation and landing logic are written directly in the script; the explosion is handled by child nodes such as **`BombComponent`**, rather than going through the standard `init_bullet` + `MovementComponent` pipeline. |

When adding a similar "cinematic" / "artillery-type" bullet, if its collision and movement differ significantly from the standard bullets, you can follow the same approach: **inherit only from `Bullet000Base`**, and fill in the scene with whatever nodes the script's `@onready` / `%` references expect.

---

## 5. Recommended Steps for Adding a New Standard Bullet

1. In `scenes/bullet/`, use one of **`bullet_000_linear_base`** / **`bullet_000_parabola_base`** / **`bullet_000_track_base`** as the parent template for the new scene, keeping the **`MovementComponent` child node's script type** consistent with the movement style you're using.
2. In `scripts/bullet/`, create a new script that **`extends`** the corresponding parent bullet class.
3. Register it in `BulletRegistry`, updating both the **`BulletType`** entry and the resource reference.
